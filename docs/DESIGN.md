# Проектные решения

## Модель v1

`model/terraforming.json` — источник истины; ручных игровых фрагментов в этой версии нет. `tools/build.py:validate` — исполняемый контракт схемы v1. Неподдерживаемые версии отклоняются; автоматических миграций пока нет, поскольку предыдущих версий схемы не существует. При будущем изменении схемы требуется явная миграция и регрессионный тест. Формат JSON выбран ради сборки стандартной библиотекой Python без скачивания зависимостей.

Классы содержат тепловую, атмосферную, водную и биосферную абстракции. Это выводы из класса, а не измеренные физические параметры. Неизвестные данные обозначены unknown. По умолчанию масса, гравитация, орбитальная инсоляция и состав атмосферы неизвестны. Размер 10–40 — настраиваемый игровой фильтр, не оценка способности удерживать атмосферу. Спутники автоматически не запрещены: достаточно крупный спутник потенциально пригоден. Экстремальные размеры ждут отдельного анализа Size Matters.

## Переходы и баланс

Каждый переход содержит стабильный id, источник, цель, технологии, энергозатраты, длительность в игровых днях, вес ИИ, политику свойств и причину. Общие требования представлены одним scripted trigger, их значения — defaults модели. Минимальный пример: `barren_to_desert` — 14 000 энергии / 20 лет. Более сложный: `toxic_to_continental` — 38 000 / 48 лет. Полная матрица генерируется из тех же данных.

Цены предварительные. Создание атмосферы и биосферы дорого, настройка под удалённый климат дороже естественного исхода. 360 дней = игровой год. Расчёт не моделирует экономику реальной партии. Стоимость не зависит от выдуманной массы. Новые ветки требуют Climate Restoration; отдельный поздний барьер токсичных миров ещё предстоит сверить с Detox. Ранние дополнительные колонии не выдаются.

В модели расширения нет циклов: новые переходы идут только от необитаемых к климатам. Однако выгодность непрямых путей через ванильную климатическую сеть пока НЕ проверена — необходимы исходные цены игры и их модификаторы. Поэтому экономическую завершённость не заявляем.

## Движок и безопасность

Генератор использует `terraform_link`, `resources.category = terraforming`, country-scope condition и `from` как планету согласно правилам CWTools. Scope конкретных триггеров и поведение движка не проверены. Ванильные файлы не заменяются. Повторяющиеся from/to с ванильными кандидатами могут дать дубли и должны быть устранены после аудита игровых данных.

Флаг `th_protected` позволяет вручную закрывать особые миры; он НЕ заменяет полную автоматическую защиту сюжетных объектов. Проверки аномалий и археологии консервативны; наличие завершённого объекта может оставить мир заблокированным. Нужен аудит фактических API и сюжетных флагов перед включением в рабочую партию.

Инициализирующих или ежемесячных событий нет. Постоянные физические переменные и миграция сейвов пока не нужны. Политика свойств `engine_default_unverified` буквально означает отсутствие собственного переноса: сохранность и пригодность полученных месторождений не подтверждены.

## Следующий необходимый этап

Получить read-only оригинальные данные 4.5.4. Затем проверить классы, scopes, техи, ванильные пары/условия, особенности кандидатов и DLC; реализовать защиту и перенос свойств; объединить расчёт цены со всей климатической сетью; включить разумный ИИ. Только после этого проводить игровой чеклист. Offline-инфраструктура продолжает работать без игры.
