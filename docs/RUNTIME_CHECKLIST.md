# Игровые испытания 0.4.0-dev

Загрузка скриптов и RU/EN выполнена; пункты реальной партии ниже пока NOT TESTED. Текущий набор инструментов запускает обычный движок и читает журналы, но не управляет нативным игровым окном. Это не headless-тесты.

## 1. Изолированный профиль и фикстуры

Не использовать основной плейсет или сейв. Для Linux с игрой и графической средой:

```sh
STELLARIS_GAME_DIR=/path/to/Stellaris make check-game
STELLARIS_GAME_DIR=/path/to/Stellaris python3 tools/smoke_game.py --with-tests
```

Команда выведет новый `/tmp/th-engine-smoke-...` и завершит процесс через 40 секунд. В этом профиле находится копия только нашего мода, тестовый маркер и отдельные authored test events. Никакие оригинальные игровые файлы не копируются. Для настоящей новой партии запустить тот же профиль без ограничения времени:

```sh
cd /path/to/Stellaris
./stellaris -userdir=/tmp/th-engine-smoke-EXAMPLE/user   -mod=/tmp/th-engine-smoke-EXAMPLE/user/mod/telluric_horizons.mod -debug_mode
```

Подставить фактически выведенный путь. Создать обычную одиночную новую органическую империю. Через три игровых дня фикстура выдаст две технологии и World Shaper для Gaia-тестов и создаст 42 тестовых мира в столичной системе. На каждом проверяются: обычная доступность, th_protected, слишком малый размер, стратегическое месторождение и восстановление доступности. Это 210 проверок предварительных условий, а не 180 проектов терраформирования. Фикстура помечает инициализацию флагом и повторно не создаёт миры на той же стране.

Извлечение только наших результатов:

```sh
python3 tools/collect_runtime.py /tmp/th-engine-smoke-EXAMPLE/user/logs/game.log
```

Код 0 означает только PASS всех 210 предварительных проверок; 1 — есть FAIL, 2 — неполный/повторный набор. Технологические выдачи, создание миров и очистка тестовых свойств существуют только в этой фикстуре. Она не входит в ZIP и не должна включаться на ценном сейве. Не использовать этот профиль как контроль экономики ИИ.

Для получения только файлов фикстуры вне проекта, без запуска игры: `python3 tools/runtime_tests.py /tmp/new-th-fixture`. Это фрагменты для тестовой копии мода, не самостоятельная установка.

## 2. Штатное меню и проекты

Для каждого тестового мира целевой класс указан в имени `TH_TEST_<route_id>`. Сначала зафиксировать патч/checksum, ОС, DLC, язык и плейсет. Проверить actual error.log, а не только успешную загрузку процесса.

1. У четырёх исходных классов без кандидата открыть штатное меню. До Climate Restoration проект должен быть заблокирован; после технологии — соответствовать условиям и размерам модели. Отдельный контроль без тестовой выдачи технологий выполняется в обычном профиле.
2. Для Barren/Cold Barren кандидата проверить дешёвую vanilla ветку. Для Toxic — кандидат с Detox/knights_detox и без них; для Frozen → Ocean — все сочетания кандидата, водного признака и Hydrocentric. Без перка дорогой fallback должен остаться доступным. Проверить число строк и какой link фактически выбран, особенно когда vanilla potential видим, а её condition закрыт.
3. Записать показанные стоимость, валюту, срок и действующие модификаторы. Сверить с generated/BALANCE_REPORT.md до общих скидок. Hydrocentric не должен применяться дважды; прямой Toxic → Arctic должен получать эквивалентную скидку пути через Ocean.
4. Проверить невозможность старта при нехватке ресурса и одно списание при достатке. Обычная империя платит только энергией, Wilderness — только биомассой. Доставок воды/газов и собственных логистических объектов нет.
5. Отменить проект на раннем и позднем сроке. Зафиксировать фактический возврат по нативным правилам; не предполагать полный refund. Повторить начало/отмену: отсутствие прибыли, двойного возврата биомассы и зависших резервов. Кандидат не должен сниматься при отмене нашего проекта.
6. Довести проект до конца движением игрового времени; ускорение времени допустимо, а change_pc/скриптовое мгновенное преобразование не заменяет этот тест. Проверить класс, колонизацию, отсутствие исходного маркера кандидата. В тестовой партии можно выбрать созданный мир и выполнить в консоли `event th_test.2`: это проверяет только итоговый класс и отсутствие активного процесса, не оплату/свойства.
7. Повторить девять климатов и Гайю из каждого источника. Для Gaia-кандидатов проверить оба состояния отдельного варианта: маркер + водный признак/Hydrocentric либо Detox/knights_detox; эти unlock-состояния оператор должен подготовить отдельно. Для Wilderness дополнительно проверить стандартную автоколонизацию и обработку очереди.
8. Убедиться, что 72 vanilla климатические пары, заселённые миры, World Shaper, Hive/Machine и Volcanic сохранили оригинальные условия. Не использовать нашу фоновую защиту как доказательство сохранности всех DLC-сценариев.

## 3. Свойства, защита и сохранения

- До/во время/после проекта записать класс, размер, модификаторы, месторождения, станцию, доступные районы, блокираторы и доход. Обычные орбитальные ресурсы обрабатывает vanilla: отдельная компенсация модом не обещается. Не должно оставаться одновременно продублированной орбитальной добычи и собственной копии её награды.
- На стратегическом/событийном/неизвестном месторождении новый проект должен быть закрыт. Завершённая археология по-прежнему может блокировать мир: это консервативное правило существования объекта.
- Проверить аномалии, чужую/неизученную систему, колонию, размеры за диапазоном, th_protected, священный/освящённый мир, предтеч, L-cluster, перечисленные сюжетные тела и состояния. Газовые гиганты, астероиды, Molten, Shattered/Broken и особые классы не получают общих новых путей.
- Прикреплённое к миру мегасооружение должно блокировать именно этот мир. Gateway или Hyper Relay на другом объекте обычной системы не должен блокировать все соседние планеты.
- Сохранить и перезагрузить до, в середине и после проекта; повторить для отмены. Записать фактическое состояние после reload, отсутствие повторной выдачи и потери защищённых наград.
- Только затем открыть отдельную копию старого сейва: около 20 колоний, Кибрекс-Альфа, мегасооружения, конкретный Size Matters. Деактивацию мода проверять на ещё одной копии; необратимые изменения откатываются исходным backup. Старую dev-партию с незавершёнными проектами не обновлять без такого испытания.

## 4. Наблюдательный прогон ИИ

Нужен отдельный нейтральный новый сейв и два одинаковых начальных состояния: с модом и контроль без него. Не использовать профиль eligibility: он выдаёт технологии и добавляет миры.

```sh
STELLARIS_GAME_DIR=/path/to/Stellaris python3 tools/smoke_game.py --ai-monitor
```

В полученном профиле загружен только дополнительный ежегодный sampler без выдачи ресурсов, технологий или планет. Он записывает `[TH AI] SAMPLE` с днём, страной, числом колоний, запасом/чистым доходом энергии и биомассы, числом активных проектов в границах. Служебные переменные очищаются после записи. Sampler также можно создать отдельно: `python3 tools/runtime_tests.py /tmp/new-th-ai-monitor --mode ai`, затем добавить его только к временной тестовой копии/контролю.

После ручного старта партии использовать штатный observer и ускорение времени. Контроль должен иметь тот же исходный сейв/seed, DLC, настройки и sampler, но не инженерные links Telluric Horizons. Сравнить число начатых/завершённых проектов, резервы, длительные дефициты, колонизацию и время тика. Требуются случаи ниже/выше границы средств/дохода, война/мир, готовая колония и уже идущий проект. При оценке помнить: sampler считает все terraforming-проекты в границах, включая vanilla, а не только наши.

Нет автоматического экономического PASS: отдельный год дефицита или отсутствие проектов не доказывает ошибку/корректность. Ищется систематическая разница с контролем и соответствие условиям реальных решений ИИ. Результаты и исправления фиксировать по конкретной партии.

## 5. Дополнительные загрузочные проверки

`--language russian` включает RU-профиль. `--baseline-error-log /outside/control/error.log` сравнивает полные нормализованные ошибки с внешним контрольным запуском. `--with-tests` и `--ai-monitor` используют разные профили и не совмещаются. Глобальные vanilla ошибки не скрываются.

Для каждой игровой строки отчёта нужны PASS/FAIL/NOT TESTED, шаги, фактические значения, версия, DLC и локальный путь к логам. Оригинальные игровые файлы, чужой мод и сейвы не публиковать и не коммитить.

Для новой Gaia-ветки проверить отсутствие World Shaper, наличие перка без Climate Restoration (только в искусственном тесте), обычный не-кандидат, готовый кандидат и сюжетную реставрацию. Сравнить стоимость/время с настоящими двумя этапами, включая общие/Ocean скидки, нативное округление и Detox-блокираторы.
