# Telluric Horizons — Planetary Engineering

Научно мотивированное терраформирование каменистых миров для Stellaris.

**Состояние: 0.4.0-dev, незавершённая разработка. Не устанавливать в основную партию.** Цель — 4.5.4 (1b4f), подтверждённая официальными новостями на 11 ноября 2026 года. Доступны оригинальные Linux-данные и движок 4.5.4. Проверены ссылки и загрузка файлов мода; терраформирование в партии, UI, ИИ и сохранения ещё НЕ проверены.

## Что реализовано

Единая JSON-модель v2 и JSON Schema, строгий валидатор, детерминированный генератор, 40 направлений из Barren / Cold Barren / Frozen / Toxic к девяти климатам и Гайе (42 link-определения с вариантами кандидатов), RU/EN причины недоступности, классификация 69 классов, упаковка и автономный CI. Игре не нужны Python или внешние библиотеки.

Ванильные климатические/DLC-переходы сохранены. Готовые кандидаты используют доступную ванильную ветку; при отсутствии нужного Detox/Hydrocentric остаётся дорогой обычный путь. Реализованы биомасса и штатные обработчики очереди Wilderness, консервативные условия ИИ, расчёт скидок Hydrocentric и защита сюжетных тел. Неизвестные/особые месторождения блокируют новый проект; обычные обрабатываются штатным терраформированием без дополнительных выдач ресурсов. Мегасооружение блокирует только прикреплённое тело, а не всю систему.

Это ещё dev-версия: поведение очереди, завершения, свойств, меню и экономики ИИ не проверено в партии. Изолированная загрузка скриптов и RU/EN локализации подтверждена реальным Linux-движком. [Точное состояние требований и остаток](docs/STATUS_RU.md).

## Разработка без игры

Требования: Python 3.11+ и GNU Make. Сторонних Python-зависимостей нет.

```sh
make lint
make test
make build
make check-generated
make package
```

Исходник: `model/terraforming.json`. Генератор: `tools/build.py`. Выход: `generated/`. Архив: `dist/telluric-horizons-0.4.0-dev.zip`. Сгенерированные файлы вручную не редактировать. После правки модели выполнить build, проверки и закоммитить generated вместе с исходником.

Проверка ссылок по законно полученной локальной копии игры (файлы используются только для чтения):

```sh
STELLARIS_GAME_DIR=/path/to/Stellaris make check-game
```

Без пути команда возвращает статус 2 (NOT TESTED). Проверка сверяет версию/checksum, все классы, технологии/модификаторы/перки/месторождения и используемые helpers, цены/сроки 72 климатических пар, 28 веток кандидатов и численно определённую сеть из 210 последующих ванильных переходов. Это не проверка выполнения скриптов.

11 ноября фактически проверен анонимный SteamCMD: вход работает, но `app_update` создаёт пустую установку, а загрузка основного депо возвращает `No subscription`. Позднее пользователь загрузил лицензированную копию. Файлы игры используются только для чтения, не копируются в репозиторий и не входят в сборку; [исторический отчёт SteamCMD](docs/STEAMCMD_REPORT.md).

Проверка загрузки реальным Linux-движком в отдельном временном профиле (требуется графическая среда, запускает окно игры и останавливает процесс через 40 секунд):

```sh
STELLARIS_GAME_DIR=/path/to/Stellaris python3 tools/smoke_game.py
```

Она проверяет монтирование тестовой копии мода и наличие относящихся к нему диагностик. Создаёт только временный профиль, не использует сейвы/плейсет пользователя и не является тестом терраформирования в партии. Путь к журналам выводится в терминал; журналы не попадают в репозиторий.

Настройки находятся в `defaults` модели: диапазон размера, списки защиты/допустимых месторождений, условия ИИ, ванильные ветки кандидатов и экономика. `ai_enabled=false` отключает новые проекты ИИ. После изменения выполнить build и все проверки. Скидка Ocean учитывается ровно один раз; цены прямых проектов замыкаются по кратчайшим путям. Расчётные сценарии, биомасса и резервы ИИ: [BALANCE_REPORT.md](generated/BALANCE_REPORT.md).

Прямой переход в Гайю требует «Меняющий миры» и «Восстановление климата». Для замёрзших/токсичных кандидатов предусмотрены отдельные варианты с преимуществами Hydrocentric/Detox. Новые обычные миры **не получают ванильную метку кандидата**: доступность определяется нашими условиями. [Технологии, кандидаты и Гайя](docs/TECHNOLOGY_RU.md).

Для старой схемы — явная миграция в новый файл с последующей проверкой результата:

```sh
python3 tools/migrate_model.py old-model.json /tmp/new-model.json
```

Миграция не читает сейвы, не меняет игровые файлы и не обновляет инвентаризацию чужого патча автоматически. Не смешивать модель и компилятор разных checkout.

Тестовые фикстуры и ежегодный монитор ИИ создаются только в отдельных временных профилях и не входят в ZIP. Команды и границы проверок: [RUNTIME_CHECKLIST.md](docs/RUNTIME_CHECKLIST.md).

## Пробная установка Linux / Windows

Только для отдельного тестового плейсета и новой партии. Сначала сохранить резервную копию пользовательских сейвов. Распаковать содержимое архива в пользовательский каталог Stellaris `mod`, чтобы рядом находились `telluric_horizons.mod` и папка `telluric_horizons`. Linux обычно использует `~/.local/share/Paradox Interactive/Stellaris/mod`, Windows — `Documents/Paradox Interactive/Stellaris/mod` (путь может быть перенаправлен OneDrive). Включить мод в отдельном плейсете лаунчера. Если он не обнаружен, проверить фактический каталог пользовательских данных.

Не применять к основному сейву до прохождения [игрового чеклиста](docs/RUNTIME_CHECKLIST.md).
